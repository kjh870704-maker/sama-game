### 시뮬레이터가 보고한 설계 과제 — 처리 결과

프리미티브가 붙자마자 헤드리스 시뮬레이션이 두 가지를 짚었다. 하나는 고쳤고, 하나는 콘텐츠 분량 문제로 M2로 넘긴다.

| 관측 | 원인 | 조치 |
|---|---|---|
| S1-08이 전투 없이 빈 성채 칸만 밟고 승리 | **승리 조건이 스펙 문서의 의도한 해법과 불일치** — 점령만 요구했다 | ✅ 수정: `수비대장 퇴각 → 성채 점령` 순차 조건 |
| S1-02가 일반·극한 모두 3턴에 100% 클리어 | 순찰을 지나쳐도 대가가 없어 잠입이 성립하지 않음 | ✅ 수정: 성문 순찰 추가 + 지참금 1회 한정(2회 발각 시 문지기 통과 불가). 극한 3턴 100% → **10턴 79%**, 인장2 **0%** / 인장3 79%로 분리 |
| S1-08 인장 2·3 획득률이 여전히 동일 | 현재 데이터의 적이 3기뿐이라 어떤 인장 수치를 조정해도 상충이 생기지 않는다 | ⬜ **M2로 이월** — 적 편성 전체와 3개 우군 루트 타이밍을 갖춘 뒤 재측정 |

#### 시뮬레이터의 한계 (해석 시 반드시 감안할 것)

AI는 **한 가지 전략만 시도한다.** 따라서:

- 인장 획득률이 **동일하게 나오는 것은 약한 신호**다. 상충이 없다는 증거일 수도, AI가 한 경로만 찾은 것일 수도 있다.
- 반대로 **획득률이 갈라지면 강한 신호**다 (S1-02가 그 사례) — 단일 전략으로도 두 인장을 동시에 만족할 수 없다는 뜻이다.
- 대화 분기는 항상 정답을 고르므로, **오답 경로의 난이도는 측정되지 않는다.**

### 게이트

> **M1을 통과하지 못하면 M2로 가지 않는다.**
> 특히 항목 9~11(성능)은 여기서 해결하지 않으면 **M2에서 Tier C 스테이지를 만나는 순간 원작과 똑같은 실패**를 반복한다.

## M2 — 상편 11스테이지

### 작업 순서

1. 남은 기믹 프리미티브 구현 (M-02, 03, 05, 08, 09, 10)
2. 맵 11종 제작
3. 스테이지 데이터 11종 작성 (일반 기준 1벌, 극한은 파생)
4. 시뮬레이터로 전 스테이지 밸런스 스윕
5. **Tier C 스테이지 저사양 실기 검증 (PF-06)** — S1-06, S1-10
6. 플레이테스트 → KPI(§11) 기준 조정

### 완료 정의

| # | 항목 |
|---|---|
| 1 | 11스테이지 × 2난이도 전부 클리어 가능 |
| 2 | `validate-stages` 무오류 |
| 3 | `sim` — AI 클리어율 0%인 조합 없음 |
| 4 | **인장 2·3이 상충** (R-5.3) — 시뮬레이터에서 두 인장 획득률이 동일하지 않을 것 |
| 5 | Tier C 스테이지가 기준 저사양 기기에서 30FPS 유지 |
| 6 | 단일 스테이지 이탈률 ≤ 8% (플레이테스트, R-11.1) |
| 7 | 극한 난이도 **동시 출시** (R-5.1 / R-10.1) |

M2와 동일한 절차. 다만:

| 부 | 추가로 필요한 것 |
|---|---|

## 상시 운영 규칙

### CI 게이트 (모든 PR)

```bash
npm run typecheck        # 타입 오류 0
npm test                 # 단위 테스트 통과
npm run validate:stages  # 스테이지 데이터 무결성
npm run sim              # 밸런스 회귀 (AI 클리어율 0% 차단)
```

### 스테이지 추가 체크리스트

- [ ] `packages/data/maps/*.json` — 맵 (영역 이름 정의 포함)
- [ ] `packages/data/stages/*.json` — 스테이지 (일반 난이도 기준 1벌만)
- [ ] `docs/prd/스테이지-스펙.md` 템플릿으로 **의도한 해법(Intended Solution) 기술**
- [ ] `validate-stages` 통과
- [ ] `sim` 클리어율 확인
- [ ] 기믹이 기존 모듈 조합으로 표현되는가? 아니면 **프리미티브를 먼저 추가**했는가?
- [ ] `packages/core`에 스테이지 ID가 등장하지 않는가? ← **설계 위반 검사**

### 리스크 재점검 주기

PRD §12의 R1(성능)·R2(난이도 스파이크)·R3(기믹 설명 부족)은 **마일스톤마다 재평가**한다. 이 셋이 원작이 실제로 실패한 지점이다.
